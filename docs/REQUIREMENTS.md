# Requirement and decision ids

Comments and test names in this repository cite short ids such as `FR-24`, `NFR-SEC-2` and `D18`,
and sometimes "architecture 4.5". This page says what each id means, in one sentence, so a reader
can look one up without any other document. Each row names a file where the rule shows. The
reasons behind the larger choices are in the [decision records](adr).

- `FR-n` is a functional requirement: something the product does.
- `NFR-xxx-n` is a quality requirement: ALN is how the code serves the product's rule that Gemini
  reads and code decides, CQ is code quality, EFF is bounded resources, SEC is security.
- `Dnn` is a design decision. `D1` to `D7` (written without a leading zero in a few comments) are
  earlier decisions of the same kind and are listed in the last decision table.
- Ids that nothing in `src`, `scripts` or `tests` cites are not defined here.

## Quality requirements

| Id         | What it means                                                                                                                                                                                                     | Where it shows                                                         |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| NFR-ALN-6  | Plans are real answers: at least five different briefs give plans whose amounts add up to their own budget and carry no demo figure unless the arithmetic gives it.                                               | `tests/unit/core/plan/plan-view.test.ts`                               |
| NFR-ALN-7  | The user stays in control: only a confirm, apply, done, delayed or undo post adds or removes a step, a read changes nothing, no lever is pre-selected and the AI draft is written only on request.                | `tests/http/read.test.ts`, `src/app/[lang]/read/[kind]/read-step.ts`   |
| NFR-CQ-7   | Task, lever and question ids are enums generated from `data/` by `scripts/generate-ids.ts`, so a link naming an id the data does not define fails when parsed.                                                    | `src/schemas/generated/ids.ts`, `tests/unit/schemas.test.ts`           |
| NFR-CQ-11  | No em dash character appears in any tracked file (source, docs, data, fixtures), and tests that need smart dashes build them from escapes.                                                                        | `scripts/check-forbidden-apis.mjs`                                     |
| NFR-EFF-6  | Memory stays bounded: a link is at most 4,000 characters, its inflated JSON at most 16,384 bytes, the reading cache 200 entries, 2 MiB and 24 hours, and the per-client rate tables are capped at 10,000 clients. | `src/server/state/token-codec.ts`, `src/server/genai/reading-cache.ts` |
| NFR-SEC-2  | User text cannot close the prompt's data block: a closing tag in any case, spacing or entity-encoded form is neutralised, so the real closing delimiter appears once, at the end.                                 | `src/server/prompts/shared/guardrails.ts`                              |
| NFR-SEC-3  | Every system prompt starts with the same guardrail text (user text is untrusted data, quote verbatim, never invent, never compute, reply only in the schema).                                                     | `src/server/prompts/shared/guardrails.ts`                              |
| NFR-SEC-9  | Resource limits: the rate limit runs before the body is read (reads six a minute with a burst of three, other posts 60 a minute), the body is at most 32 KiB, the text 2,000 code points and a read 40 seconds.   | `src/server/ratelimit/rate-limit.ts`, `src/server/http/form-body.ts`   |

## Design decisions

| Id  | What it means                                                                                                                                                                                                                      | Where it shows                                                              |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| D06 | Left out on purpose: merging old steps into a baseline, rotating the seal key and de-duplicating simultaneous identical reads. A plan stops at 40 steps with a page that says so ("This plan has reached 40 steps").               | `src/core/plan/apply.ts`, `src/server/genai/reading-cache.ts`               |
| D07 | The family update is the one model-written text: drafted from facts the code supplies, and rejected if any number in it is not among those facts.                                                                                  | `src/core/messages/draft-check.ts`                                          |
| D08 | An accepted draft is kept in the reading cache under a hash of its facts, never in the link; a cache miss shows the template again.                                                                                                | `src/server/pipeline/draft-family-update.ts`                                |
| D09 | The budget split is computed once, at the brief, and never again: a lower budget or more guests shows as a gap, and only Move money changes allocations.                                                                           | `src/core/budget/frozen-split.ts`                                           |
| D10 | One booking path: marking a booking task done with an amount books its category at that amount; without an amount it only marks the task done.                                                                                     | `src/core/plan/apply.ts`, `src/core/timeline/task-progress.ts`              |
| D11 | A delay is stored as the absolute date before which the task cannot start (today plus N, 1 to 60 days), so a link opened later shows the same schedule.                                                                            | `src/core/timeline/task-progress.ts`                                        |
| D12 | Move money takes from headroom first, then from "save" categories and then "standard" ones, each down to half its frozen allocation (contingency to 5 percent of the budget); break-even is an integer scan.                       | `src/core/budget/giver-eligibility.ts`, `src/core/quotes/break-even.ts`     |
| D13 | Priorities are revised only in the change form; they change which levers are allowed and which categories may give money, and never re-split the budget.                                                                           | `src/app/[lang]/p/[token]/_change/change-values.ts`                         |
| D14 | Diet and venue limits are served by asking (each adds a vendor question); other must-haves and needs are kept as the user's own words, shown as noted and never a decision input.                                                  | `src/server/knowledge/cross-file-integrity.ts`                              |
| D15 | There are two budget profiles, wedding and celebration; an unanswered priority counts as standard, and amounts round to Rs 100 below Rs 1 lakh and to Rs 1,000 above.                                                              | `src/core/money/rounding.ts`                                                |
| D16 | The model ladder gives 20 seconds to the first model, 18 to the second and the rest of 40 to the third (only with 15 left, so two timeouts end a read at 38); a hint under each read button says a read can take up to 40 seconds. | `src/server/genai/gateway.ts`, `src/components/form/post-form.tsx`          |
| D17 | Quota is assumed, not measured: about 20 requests a day per model per key project, one project since D46, resetting at midnight Pacific time.                                                                                      | `src/server/genai/exhaustion.ts`, `src/server/config/clock.ts`              |
| D18 | The live read is protected: past 80 percent of an assumed allowance the exact example texts are served from their committed recording and labelled so, and each instance and each client has a daily cap.                          | `src/server/genai/exhaustion.ts`, `src/server/pipeline/example-readings.ts` |
| D23 | Page weight is measured and published by a script, not enforced by a CI gate.                                                                                                                                                      | `scripts/measure-pages.mjs`                                                 |
| D27 | The footer says, in the page's language, that no database is kept, the plan is encrypted inside the link and Google Cloud request logs may hold the link.                                                                          | `src/components/layout/site-footer.tsx`                                     |
| D29 | A decision is kept when its key is in both versions with an equal value; the counter counts both the "Kept" and "Kept, ask again" lists.                                                                                           | `src/core/plan/kept.ts`                                                     |
| D30 | Amounts are written "Rs 7,50,000" in both languages with the lakh or crore word beside them; the rupee sign is accepted as input only.                                                                                             | `src/core/rupees/format.ts`                                                 |
| D31 | Id enums are generated from the data, and display quotes and change sources are capped at 80 UTF-8 bytes, because Zod's length counts UTF-16 units.                                                                                | `scripts/generate-ids.ts`, `src/schemas/plan/short-text.ts`                 |
| D32 | The revision page compares the latest change with the version just before it, while the lever section always works on the current plan.                                                                                            | `src/core/plan/plan-version.ts`, `src/core/plan/diff.ts`                    |
| D33 | The golden recorder keeps model calls few: it records the family-update draft in one language only, Hindi.                                                                                                                         | `scripts/record-golden.ts`                                                  |
| D34 | Hindi number words (ek to das, dedh, dhai, sava and so on), in Latin and Devanagari script, are parsed when a unit (hazaar, lakh, crore) follows; English number words are not.                                                    | `src/core/rupees/number-words.ts`                                           |
| D35 | A narrow table stays a table inside a focusable, labelled scroll region, and a post lands on its section, and a status line near the top of the page says what changed.                                                            | `src/components/table/scroll-table.tsx`                                     |
| D36 | A quote longer than 160 characters makes that one field unverified (`quote-too-long`) and the reading continues; it is not a failed reply.                                                                                         | `src/core/grounding/quote-match.ts`                                         |
| D37 | A data row's `basis` is the author's stated assumption, and no source, survey or link is named as where a figure came from.                                                                                                        | `src/schemas/data/planning-row.ts`                                          |
| D38 | The start page speaks of "your event" with an occasion picker, and each occasion maps to exactly one budget profile in `data/budget-weights.yaml`.                                                                                 | `src/schemas/data/budget-weights.ts`                                        |
| D39 | A link is capped at 4,000 characters; a step that would exceed it is refused with a 422 page ("This plan's link is full") and the plan is unchanged.                                                                               | `src/server/http/post-step.ts`                                              |
| D40 | A small celebration has its own lead times and durations in a `celebration` block on each kept task, so a six-week birthday is not scheduled like a wedding.                                                                       | `src/core/timeline/task-selection.ts`, `data/tasks.yaml`                    |

## Other labels in comments

- `G1` to `G4` are the four model calls: G1 reads a brief, G2 reads a vendor quote, G3 reads a
  change message and G4 drafts the family update. See [GENAI_SERVICES.md](GENAI_SERVICES.md).
- "arch n" is short for "architecture n" (see the table below), for example "arch 8" is the
  accessibility work (anchors, labels, islands), described in [ACCESSIBILITY.md](ACCESSIBILITY.md).
- "spec 7" or "spec section 7" (older comments) is the rule that every rupee figure carries a
  provenance label and that money follows the guest count by fixed rules; read
  [ADR 0001](adr/0001-pure-core.md) and [ADR 0003](adr/0003-planning-knowledge-as-data.md). On the
  plan page it also labels the line saying how a plan version was made (read by AI, with its count,
  or an example).
- `C4` to `C8` and "spec n" or "spec n.n" (for example "spec 6.5") name capabilities and sections of a
  product specification that is not published. What each one does is described in the [README](../README.md).
